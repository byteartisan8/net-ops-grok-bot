# netbox/ - owner: session 03-netbox

NetBox is the lab's **source of truth (intent)**. The seeder fills it from `contract/topology.yaml`; after that,
everything that needs intent (the bot, the drift check, Zabbix's BSM) reads it **from NetBox only**. Edit NetBox and
the intent changes. Design decisions and verification: [`docs/reports/03-netbox.md`](../docs/reports/03-netbox.md).

| Path | What |
|---|---|
| `compose.yaml` | `netbox` (172.30.10.30, UI/API on `127.0.0.1:8000`), `netbox-worker` (172.30.10.31, sends webhooks), `netbox-postgres`, `netbox-redis`, `netbox-redis-cache` (internal network only) |
| `netbox.mk` | `make netbox-*` targets (included by the root `Makefile`) |
| `tools/` | Python package `netsim-netbox-tools` (`netsim_netbox`): `netbox-bootstrap`, `netbox-seed`, `netbox-intent` |
| `tests/integration/` | tests against a throwaway NetBox stack (`make netbox-test-integration`) |

Pinned: `netboxcommunity/netbox:v4.7.3-5.1.1` (NetBox 4.7.3), `postgres:16.15-alpine3.24`,
`valkey/valkey:8.1.10-alpine3.24` (same image as `core`).

## Quick start

```bash
make netbox-up        # start + wait healthy (~4 min the first time: migrations) + provision the API tokens into .env
make netbox-seed      # make NetBox match the topology; a second run reports "0 changes"
uv run netbox-intent render-all --out build/intent --check-golden --yanglint
uv run netbox-intent blast-radius hub-a
```

UI: <http://127.0.0.1:8000> as `NETBOX_SUPERUSER_NAME` / `NETBOX_SUPERUSER_PASSWORD` from `.env`.

| Target | Does |
|---|---|
| `netbox-up` / `netbox-down` | start (and bootstrap tokens) / stop the five containers (volumes kept) |
| `netbox-bootstrap` | wait for NetBox, create or verify `NETBOX_TOKEN_RW` / `NETBOX_TOKEN_RO` in `.env` |
| `netbox-seed` | seed (idempotent); `SEED_ARGS="--prune"` etc. Used by `make seed` |
| `netbox-plan` / `netbox-prune` | dry run (with prune) / seed and delete stale `netsim-lab` objects |
| `netbox-render` / `netbox-bsm-spec` | rendered intent into `build/intent/` (validated) / BSM spec on stdout |
| `netbox-test` / `netbox-test-integration` | unit tests (recorded NetBox, no containers) / real NetBox (throwaway stack) |
| `netbox-ps`, `netbox-logs`, `netbox-shell` | status, logs, `nbshell` |

## Data model (contract section 10)

| Lab concept | NetBox |
|---|---|
| everything seeded | tag `netsim-lab` (`--prune` deletes only such objects) |
| PE router | device, platform `netsim-clixon`, role `hub` / `spoke`, site `DC-A`... in region `Lab`, type `NetSim PE` |
| management | interface `Mgmt0` (virtual, mgmt only) with the labnet `/24`, device `primary_ip4` |
| loopback | interface `Loopback0` (virtual) with the `/32`, IP role `loopback` -> YANG `system/loopback-ipv4` |
| physical interface | `1000base-t`, MTU, description, custom field `if_role` = `core-uplink` / `access` (YANG `type`) |
| subinterface | virtual interface with `parent`; 802.1Q mode `tagged`, its single tagged VLAN = the dot1q VLAN |
| VLAN | IPAM VLAN in group `l2vpn-acs` (scope region `Lab`), one per service, named after it |
| customer | tenant in group `L2VPN Customers`, custom field `sla_tier` (`gold` / `silver`) |
| pseudowire | L2VPN `SVC-0001-primary`, type `vpws`, `identifier` = vc-id, tenant, tag `l2vpn-pw`, custom fields `service_id`, `pw_role`, `spoke_ac` |
| PW ends | hub end = the L2VPN's termination (hub subinterface); spoke end = `spoke_ac` (object custom field -> spoke subinterface) |
| change notification | webhook + event rule -> `POST http://172.30.10.50:8090/hooks/netbox` (HMAC-SHA512 `X-Hook-Signature`) |

Why the spoke end is a custom field: NetBox allows one L2VPN termination per interface, and the primary and backup PWs
of a service share the spoke's subinterface. Every hub subinterface carries exactly one PW.

## Tokens

NetBox 4.7 tokens are v2: `nbt_<key>.<secret>`, header `Authorization: Bearer <token>`, plaintext generated by NetBox
and shown once. `netbox-bootstrap` obtains them over the REST API and writes them into `.env`:

- `NETBOX_TOKEN_RW`: superuser token (seeding, journal entries);
- `NETBOX_TOKEN_RO`: user `netsim-bot`, view-only permission (no accounts, no webhooks) and a token without write
  ability: what the bot, the renderer and the BSM spec use.

A valid token in `.env` is kept; an invalid one (e.g. after `make clean`) is replaced.

## netbox-intent

```text
netbox-intent render spoke-2 [--json]                    # intended config (--json: canonical RESTCONF JSON)
netbox-intent render-all --out DIR [--check-golden] [--yanglint]
netbox-intent bsm-spec [--out FILE] [--normalized]       # contract section 9.3 document, from NetBox
netbox-intent services HOST | expected-pws HOST | blast-radius HOST | service SVC-0002   [--json]
netbox-intent journal device:spoke-2 "message" [--kind success]   # RW token
netbox-intent problems                                   # NetBox data that cannot be turned into intent
netbox-intent snapshot [--out FILE]                      # raw objects the intent is built from
```

Library: `from netsim_netbox.intent import load_intent, render_device, bsm_spec, services_on_device, expected_pws,
blast_radius, service_detail, write_journal`. Settings: `NETBOX_URL` (from a labnet container
`http://172.30.10.30:8080`), `NETBOX_PUBLIC_URL`, `NETBOX_TOKEN_RO`, `NETBOX_TOKEN_RW` (environment, else `.env`).
